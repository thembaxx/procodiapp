# Little Less privacy and security audit

Audit date: **9 October 2026 (UTC)**. Baseline: `c7d79922ff379c2ed63340f74f2fdf0149b2f76c`. Public deployment: <https://procodiapp.vercel.app>. The remediation is recorded in the Git commit containing this report.

**The application has stronger safeguards after this audit, but public-launch readiness remains blocked by unavailable live storage and missing operator/private-contact configuration.** No critical exploitable issue was identified within the reviewed scope. This is a code review and targeted technical audit, not a legal compliance certification or exhaustive penetration test.

## Scope and method

Reviewed all application API handlers; promotion/source validation and AI extraction; local/Supabase storage and SQL permissions; browser preferences, bookmarks and IndexedDB; service-worker install/update/cache boundaries; generated HTML and JSON-LD; HTTP security headers; dependencies; Docker packaging; and both GitHub workflows.

Used read-only requests against the public deployment. Mutating, hostile-input and concurrency checks used local fixtures or an isolated PostgreSQL 17 container, with no public database writes, paid-provider discovery, brute-force login attempts or load tests. Checked the complete available eight-commit Git history with checksum-verified Gitleaks 8.30.1, plus targeted key-pattern checks. Ran `pnpm audit --prod` and the complete dependency audit; neither reported a known advisory at audit time. Inspected client JavaScript for credential patterns and public source maps.

Hosting/database consoles, real provider credentials, logs, backups, processor contracts and account IAM were not available. GitHub branch-protection inspection returned `403 Resource not accessible by integration`. Scheduler variables/secrets and private vulnerability-reporting configuration were not established. These are **unverified**, not assumed absent or safe. Docker packaging was reviewed; the deployed OS/base-image packages, TLS cipher configuration and infrastructure were not exhaustively scanned.

## Data inventory and trust boundaries

| Data                                                             | Location / recipients                             | Purpose and retention                                                                                                                                                                                       |
| ---------------------------------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Theme, view, effects setting, saved promotion IDs                | Browser local storage                             | User preferences; stays until cleared. No account or remote bookmark sync.                                                                                                                                  |
| Validated offer snapshot                                         | Browser IndexedDB                                 | Offline access. Stale/expired offers are hidden, not automatically deleted from disk. Replaced by later snapshots or cleared with site data.                                                                |
| App shell, fonts, icons, scripts and theme manifests             | Browser Cache Storage                             | Offline app. One prior build may remain for open tabs; unrelated caches are not removed.                                                                                                                    |
| Promotion criteria, evidence, code, expiry and source URL        | Local volume or Supabase; public app/API/Markdown | Public promotion listings. Only schema-approved fields leave storage. Quotes can contain information already present on public source pages.                                                                |
| Promotion ID, enumerated report reason, submission time          | Local private file or Supabase                    | Review incorrect listings. Eligible for deletion after 30 days; removed on the next successful report write or scheduled cleanup. No free text, account ID, email or stored reporter address.               |
| Secret-keyed client limiter identifier                           | Memory on one Node instance, or Supabase          | Abuse prevention. Address identifiers rotate daily; rows expire after one minute, or ten minutes for the non-personal shared budget. Expired rows are deleted during subsequent limiter/cleanup operations. |
| Network address, user agent, requested URLs and operational logs | Hosting/ingress providers                         | Necessary delivery/operations; actual collection, region and retention remain unverified. The application not storing raw IPs does not mean the host never sees them.                                       |
| Retailer search query and public page text                       | Tavily/OpenAI when configured                     | Server-side discovery and extraction. Shopper bookmarks/search text are not submitted. Provider retention, training controls and cross-border arrangements require operator verification.                   |
| Credentials                                                      | Server runtime / scheduler secrets                | OpenAI, Tavily, Supabase, cron and rate-limit authority. Never use `NEXT_PUBLIC_*`, repository files, client assets or logs for these values.                                                               |

The app has no accounts, payment processing, advertising cookies, analytics SDK, push subscriptions or geolocation collection in the reviewed implementation. Native sharing sends public promotion details only after the user invokes it. Opening a source leaves Little Less for a site with its own policies. Offline browser data is not encrypted by the application; users of a shared/unlocked device can access it through the browser. Clearing site data removes preferences, bookmarks, IndexedDB and app caches; uninstalling a launcher icon alone may not.

## Findings and remediation

Severity indicates practical impact and prerequisites; a code-level issue is not proof of an observed production breach.

| ID  | Severity            | Finding                                                                                                                                                      | Outcome                                                                                                                                                                                                                                                                                                                                     |
| --- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F01 | Medium              | Limiter identifiers used unsalted SHA-256. An observer of the table could cheaply test guessed IPv4 addresses and link repeated identifiers.                 | Replaced with HMAC-SHA-256 using a separate strong secret. Address keys rotate daily. The non-personal global budget stays stable across midnight. Production/distributed limiting fails closed without a strong key.                                                                                                                       |
| F02 | Medium              | Reports had indefinite retention and no scheduled cleanup.                                                                                                   | Added 30-day active-storage eligibility, serialized/atomic private local compaction, service-role-only database report/cleanup RPCs, and cleanup before scheduled discovery. SQL migration and a functioning schedule are still required on the real deployment. Backups remain outside app cleanup.                                        |
| F03 | Medium              | The limiter SQL's `ON CONFLICT (client_key)` is ambiguous with its named argument under default PostgreSQL settings, preventing successful RPC execution.    | Reproduced against isolated PostgreSQL and corrected using the explicit primary-key constraint. Tests also verify one winner under twelve concurrent attempts. Applying the migration remotely remains an operator action.                                                                                                                  |
| F04 | Medium, conditional | `readCache` spread the raw stored object into public API responses. An unexpected private top-level field in a cache row could be disclosed.                 | Replaced with a bounded public projection/schema for the whole cache and client snapshots. Tests place an accidental private field in storage and verify its absence. No such live disclosure was observed. Malformed records now fail closed instead of silently falling back to seed data.                                                |
| F05 | Medium              | Report byte limits had no app-level body-read deadline; a slow body could hold resources. External/database JSON responses were also read without byte caps. | Added a five-second report deadline, a 2KB request cap, strict report fields, bounded streamed provider/database/source reads and safe errors. Tests cover never-ending streams and uncooperative cancellation. Edge connection/request limits remain necessary.                                                                            |
| F06 | Medium, conditional | Source fetches trusted every subdomain under an approved parent; persisted offer URLs accepted any credential-free HTTPS host.                               | Shared validation now permits reviewed exact hosts and their explicit `www` variants, enforces the relevant retailer boundary and rejects private literals, arbitrary hosts and unreviewed subdomains. Every source redirect is rejected before requesting the new page. This is not DNS pinning; protect server egress as described below. |
| F07 | Low                 | Provider/database redirects were implicitly permitted, and storage URL configuration was not constrained to a safe HTTPS origin.                             | Validate the storage origin before sending credentials and reject provider/database redirects. Tests verify invalid origins never invoke fetch. Scheduler URL validation also rejects paths, credentials and non-HTTPS origins.                                                                                                             |
| F08 | Medium              | A public visitor could trigger an expensive complete discovery every minute across the shared budget.                                                        | Public discovery is now limited to one attempt every ten minutes, alongside a one-minute client cooldown. The atomic distributed RPC bounds windows to 1–600 seconds. This reduces cost, but does not prevent bots consuming the budget or substitute for provider spending caps. Authenticated scheduled discovery is separate.            |
| F09 | Low                 | CI used mutable action tags and inherited token permissions.                                                                                                 | Pinned actions to reviewed commit SHAs, explicitly limited workflow permissions to repository read, and pinned the database-test image digest. A new isolated database CI job verifies migration, ACLs, RLS, retention and concurrency.                                                                                                     |
| F10 | Low                 | Cron accepted any nonempty configured secret; the scheduler did not validate its destination and printed entire discovery responses.                         | Require at least 32 characters at the endpoint and scheduler, retain timing-safe comparison, reject redirects, bound job duration and emit minimal success/failure logs. Secrets must still be randomly generated and rotated by the operator.                                                                                              |

Offline availability hardening: precached theme manifests are served before a network attempt, and IndexedDB operations have deadlines with safe empty-state fallback if device storage stalls. A browser fixture deliberately blocks IndexedDB and checks that search remains usable with no displayed offers. The full-suite WebKit loading failure was observed before these changes; the revised seven-test WebKit PWA suite passed twice (14 checks), including stale/corrupt data and deliberately blocked storage. This does not identify every underlying browser-engine failure or replace real-device testing.

Additional hardening: `script-src-attr 'none'` blocks inline event handlers; embedded frames/media are denied; deployment tracing excludes runtime data, environment files and test artifacts. Production retains self-hosted fonts/assets, no `unsafe-eval`, escaped React text and JSON-LD, framing protection, `nosniff`, restrictive device permissions and no-store API responses.

## Remaining risks and launch actions

| Priority                                     | Status / evidence                                                                                                                                                               | Required action                                                                                                                                                                                                                                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **High: availability / launch blocker**      | Live `/api/health` returned **503** with only `{"status":"unavailable"}`. The public offers response contained initial listings with `updatedAt: null` and no discovery checks. | Configure durable storage in the actual Vercel deployment, apply the current SQL migration, set `RATE_LIMIT_SECRET`, verify successful report/refresh writes, restart durability and scheduled cleanup. Do not call initial listings proof of working discovery.                                     |
| **High: privacy readiness / launch blocker** | Live privacy page had no private contact. Operator identity, processor regions, log/backup retention and cross-border/provider arrangements are not verified.                   | Supply `OPERATOR_NAME` and `CONTACT_EMAIL`; confirm hosting/Supabase regions and contracts; document log/backup deletion, data-subject requests and incident handling. Review applicable POPIA responsible-party/Information Officer and notification obligations. No compliance conclusion is made. |
| Medium: CSP defense                          | Document CSP permits inline script blocks needed by current streamed hydration and static offline replay. No source-text XSS was reproduced; event attributes are now blocked.  | Plan nonce/hash-based script authorization with an explicit offline-shell policy and full PWA testing. A permissive inline-script directive is weaker defense even when current sinks are escaped.                                                                                                   |
| Medium: abuse and spending                   | Public writes and discovery are intentionally unauthenticated. Application limits do not protect the ingress, prevent all database reads, or enforce provider dollar limits.    | Verify trusted header replacement, edge request/connection/body limits, WAF/rate controls and provider spending caps/alerts. Keep forwarding trust disabled until ingress behavior is confirmed.                                                                                                     |
| Medium: source/AI integrity                  | Quoted evidence and strict schemas do not establish that every inferred term belongs to the same offer or that a code works. Approved DNS is not pinned to public IPs.          | Review unusual extracted offers; never relabel them checkout-tested without evidence. Restrict server egress to intended public services, deny private/metadata ranges at the network boundary and review additional hosts explicitly. No unauthorized private-network request was observed.         |
| Medium: account and release controls         | Branch protection, private reporting, Vercel/Supabase IAM, MFA, secrets rotation, scheduler settings and backups could not be inspected. Deployments are automatic on main.     | Verify least privilege, MFA, protected main/required checks, secret scanning/private reporting, rollback and tested restore. A committed migration is not evidence that remote database grants are correct.                                                                                          |
| Low: device/privacy boundaries               | Local browser data persists until cleared; local-file limiting is per process.                                                                                                  | Explain shared-device visibility and clearing site data; use Supabase for multiple instances. Keep runtime data on a private persistent volume, with access restricted to the non-root app user.                                                                                                     |

Before enabling production writes, apply the database migration and configure the secrets. The migration removes already-expired limiter records and reports older than 30 days. Production mutation routes reject missing/weak rate-limit configuration; no insecure ephemeral production fallback was added. The site can still render public information and initial source listings when no local cache exists, while readiness remains truthful.

## Verification evidence

- Dependency scans: zero reported advisories across production and complete dependency graphs at audit time. This does not rule out unpublished vulnerabilities.
- Gitleaks 8.30.1: no detected secrets in the available eight-commit history. Additional targeted history/client-bundle patterns found no credential matches. New build: 15 client JS files, no published client source maps, no packaged `.data` files. Pattern scans can miss unsupported formats.
- Live read-only probes: home/privacy/offers served expected public content; unauthenticated cron returned 401; `.env`, `.git/config`, `.data/reports.jsonl` and schema paths returned 404. These probes are not a complete enumeration of host configuration.
- Live Chromium visit/search/privacy navigation: no third-party browser request origins, cookies or page errors observed in that sampled session. Hosting logs and server-provider requests are outside that browser observation.
- Unit checks: 38 tests, including accidental private cache fields, expired reports, concurrent local writes, HMAC rotation, rate windows, slow input, hostile URLs/redirects and database credential boundaries.
- PostgreSQL 17: schema applied twice; unprivileged actual report reads refused; RLS/ACLs and service-role RPC access verified; invalid report reasons/windows/identifier shapes refused; old reports/limit rows removed while fresh reports remain; exactly one accepted request among twelve concurrent limiter attempts.
- Final local browser release: **90 passed, four intentional browser-specific skips**. The regression suite covers all three views, themes, accessibility, escaped hostile offer strings, CSP event-handler enforcement, API errors and real service-worker offline/update flows in Chromium, Firefox and WebKit. Exact release results are recorded by CI.

Re-run this audit after changes to hosting, storage, provider access, analytics, accounts, payments, notifications or the offline cache. Configuration readiness can be checked without exposing secret values using `pnpm check:production`; a pass is not a substitute for the live checks above. See [production.md](production.md) for migration and launch verification.
